# Synapse 시작 가이드 (처음 쓰는 분용)

> **Synapse가 뭔가요?**
> 말로 요청하면 AI가 **그 일을 대신 해주는 작은 자동화 에이전트**를 직접 만들어 줍니다.
> 예) "매일 아침 9시에 경제 뉴스를 요약해서 내 메일로 보내줘" → 뉴스 수집 → 요약 → 메일 발송을
> 하는 에이전트가 **자동으로 만들어지고**, 스케줄에 걸면 매일 알아서 돕니다. (Docker 불필요)

이 문서만 따라 하면 **설치 → 에이전트 만들기 → 메일 받기**까지 끝납니다.

---

## 1. 5분 요약 (제일 빠른 길)

```
1) 백엔드 실행  → 2) 프론트 실행  → 3) .env에 Gmail 정보 입력
4) "에이전트 생성"에서 한국어로 요청 입력 → 생성
5) "에이전트 관리"에서 [실행]으로 1회 테스트 → 메일 도착 확인
6) "스케줄"에서 cron 등록 → 매일 자동 발송
```

> ⚠️ **에이전트를 만들기만 하면 자동으로 돌지 않습니다.**
> 자동 발송을 원하면 5번(테스트) 후 6번(스케줄 등록)을 꼭 해야 합니다.

---

## 2. 설치 & 실행

### 사전 준비
| 항목 | 버전 |
|------|------|
| Python | 3.10+ |
| Node.js | 18 LTS+ |

### 백엔드 실행
```bash
cd Synapse/backend
pip install -r requirements.txt      # 최초 1회
uvicorn app.main:app --reload --host 0.0.0.0 --port 2004
```
- 동작 확인: 브라우저에서 [http://localhost:2004/docs](http://localhost:2004/docs) (API 문서)

### 프론트엔드 실행 (새 터미널)
```bash
cd Synapse/frontend
npm install                          # 최초 1회
npm run dev
```
- 브라우저: [http://localhost:2003](http://localhost:2003) (자동으로 열립니다)
- 프론트는 `/api` 요청을 백엔드(`:2004`)로 프록시합니다. **백엔드를 먼저** 켜세요.

---

## 3. 환경 설정 (.env) — 메일 발송에 필수

`Synapse/backend/.env` 파일에 아래를 채웁니다.

```env
# LLM (요약에 필요) — Anthropic 키
ANTHROPIC_API_KEY=sk-ant-...

# 메일 발송 (Gmail 권장)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your_id@gmail.com
SMTP_PASSWORD=앱_비밀번호_16자리
SMTP_FROM=your_id@gmail.com
```

> **Gmail 앱 비밀번호가 꼭 필요합니다.** 일반 로그인 비밀번호로는 메일이 안 나갑니다.
> 발급: [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) → 16자리 입력.
> (네이버 메일은 SMTP 로그인을 거부하는 경우가 많아 Gmail을 권장합니다. 받는 주소는 네이버여도 됩니다.)

`.env`를 바꾼 뒤에는 백엔드를 재시작하세요.

## 4. 에이전트 만들기 (핵심)

### 4-1. 요청 작성
좌측 메뉴 **"에이전트 생성"** → 입력창에 **하고 싶은 일을 한국어로** 적습니다.

좋은 요청 예시:
```
매일 아침 9시에 경제 뉴스를 요약해서 hong@example.com 으로 메일 보내줘
```
요청에 다음을 넣으면 더 정확합니다.
- **무엇을**: 경제 뉴스 / IT 뉴스 / 특정 키워드
- **어떻게**: 요약해서 / 정리해서
- **어디로**: 받는 사람 **이메일 주소** (예: `hong@example.com`)
- **언제**: 매일 아침 9시 / 1시간마다 (스케줄 등록 시 사용)

### 4-2. (선택) Critic 모드
생성 화면의 **"Critic 모드 (Dual Supervisor)"** 체크박스:
- **켜면(권장)**: 만들면서 **실제로 1회 시험 실행(dry-run)** 해보고, 결과가 나쁘면
  스스로 프롬프트/도구를 고쳐 다시 만듭니다. 품질↑, 시간은 조금 더 걸립니다.
- **끄면(Solo)**: 빠르게 1회 생성. 검증 없이 바로 등록.

### 4-3. 생성 결과
생성이 끝나면 보통 이런 도구들이 자동으로 만들어집니다.
```
뉴스 수집(fetch) → 요약(summarize) → 메일 발송(send_email)
```
> 메일을 보내라고 했는데 **발송 도구가 빠지는 일**은 시스템이 자동으로 막습니다
> (요청에서 이메일 주소를 추출해 표준 발송 도구를 자동 삽입).

---

## 5. 실행하고 메일 받기

좌측 **"에이전트 관리"** → 만든 에이전트 선택.

1. **필수 설정 확인**: SMTP/LLM 키가 ✓인지 확인. ✗면 `.env`를 채우고 백엔드 재시작.
2. **[실행] 버튼**: 도구 파이프라인을 **1회 즉시 실행**합니다.
   - 성공하면 잠시 후 메일이 도착합니다.
   - 실패하면 **어디서/왜 실패했는지**(도구·줄번호·사유) 화면에 표시됩니다.
3. 문제없이 메일이 오면 → 다음 단계(스케줄)로.

---

## 6. 자동 실행 (스케줄 등록)

좌측 **"스케줄"** → 에이전트 선택 → cron으로 주기 등록.
- 예: `10 9 * * *` = 매일 09시 10분
- 등록하면 서버가 켜져 있는 동안 **자동으로 주기 실행**됩니다.
- **즉시 실행** 버튼으로 스케줄 동작도 바로 테스트할 수 있고, **실행 로그**도 확인됩니다.

> 현재 스케줄은 **사람이 직접 등록**합니다(요청에 "매일 9시"라고 써도 자동 등록되지는 않음).

---

## 7. 에이전트 삭제 & 도구 정리

- **에이전트 관리 → 삭제**: 그 에이전트의 **전용 도구만** 삭제됩니다.
  - 여러 에이전트가 공유하는 **공용 도구**(뉴스 파서 등)와 **다른 에이전트가 쓰는 도구**는
    "도구 청소부"가 **자동으로 보호**합니다. 삭제 후 보호/보존 내역이 알림으로 표시됩니다.
- **중복/잔여 도구 정리**: `POST /api/tools/cleanup` 호출 시
  - 등록된 에이전트가 없는 **고아 도구**를 제거하고,
  - 한 에이전트 안의 **단계별 중복 도구**를 1개로 정리합니다.

## 8. 잘 안 될 때 (문제 해결)

| 증상 | 확인 / 해결 |
|------|-------------|
| **메일이 안 와요** | ① `.env`의 `SMTP_USER/PASSWORD`(앱 비밀번호 16자리) 확인 ② "관리"의 필수 설정 ✓ ③ [실행] 결과 메시지 확인 ④ 스팸함 확인 |
| **요약이 비어 있어요 / 제목만 와요** | 소스가 본문을 못 줬을 수 있음. Critic 모드로 다시 생성하면 자가 점검·보정합니다 |
| **생성이 자꾸 실패/오래 걸려요** | 일시적 LLM/네트워크 문제는 내부 "하네스"가 자동 재시도합니다. 반복되면 요청을 더 구체적으로(소스·이메일·주기 명시) |
| **메일 도구가 안 만들어졌어요** | 요청에 **받는 이메일 주소**를 넣으세요. 주소가 있으면 발송 도구가 자동 삽입됩니다 |
| **`ModuleNotFoundError: app`** | 반드시 `backend/` 폴더에서 uvicorn 실행 |
| **프론트에서 API 연결 실패** | 백엔드(`:2004`)를 먼저 실행했는지 확인 |
| **메뉴 두 개가 같이 켜져요** | 해결됨(네비게이션 정확 매칭). 새로고침/HMR로 반영 |

## 9. 내부 동작이 궁금하다면 (강점 요약)

Synapse는 "그럴듯한 설계도"가 아니라 **실제로 실행되는 Python 도구**를 만들고, 안정적으로
돌도록 여러 안전망을 둡니다.

- **하네스(Harness)**: LLM 응답이 깨지거나 도구가 일시적으로 실패해도, 재시도·복구로
  전체가 멈추지 않게 합니다. (생성 단계 + 실행 단계 2종)
- **서로 평가(Dual Supervisor)**: Critic 모드에서 Builder↔Critic이 결과를 실제로 보고
  평가→개선을 반복합니다.
- **결정적 보정**: 뉴스 수집은 검증된 공용 파서를 쓰게 하고, 발송이 필요한데 메일 도구가
  빠지면 표준 발송 도구를 자동으로 채워 넣습니다.
- **도구 청소부**: 삭제·정리 시 공용/필수/공유 도구를 자동으로 보호합니다.

자세한 기술 내용은 [`docs/구현_현황.md`](구현_현황.md) 참고.

## 10. 한눈에 보는 전체 흐름

```
[에이전트 생성]  말로 요청 → (Critic 모드면 시험 실행+자가개선) → 실행 가능한 도구 생성
        │
        ▼
[에이전트 관리]  필수 설정 ✓ 확인 → [실행]으로 1회 테스트 → 메일 도착 확인
        │
        ▼
[스케줄]        cron 등록 → 매일/주기적으로 자동 실행 → 메일 자동 발송
```
