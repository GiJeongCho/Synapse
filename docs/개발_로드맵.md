> 최종 수정: 2025-06

---

## 확정된 방향

- **Vector DB**: Milvus (개발=Milvus Lite 로컬 `.db`, 프로덕션=Docker/서버로 무변경 전환)
- **핵심 UX**: 문서 클릭 → 청크를 품질/중요도 기반 **색 농도**로 표시 → 연한(저점수) 청크 수정/삭제 → **재임베딩 재저장** → RAG 검색 정확도 향상
- **고도화**: Neo4j 그래프 저장 + 관계 그래뉼래리티(단어-문장 / 문장-문장 / 단어-단어)

## 데이터 흐름 (Phase 1)

```
문서 업로드 (PDF/뉴스/법령)
    ↓
[1] 문서타입 분류 (휴리스틱 + LLM 폴백)
    ├── 논문  → LLM Regex Splitter
    ├── 법령  → Split-then-Merge (조항 단위)
    └── 뉴스  → Recursive Splitter
    ↓
[2] Adaptive Chunking (여러 청커 병렬 → 5지표 채점 → 최고점 채택)
    ↓
[3] 크기 정규화 (>1,100 토큰 분할 / <100 토큰 병합)
    ↓
[4] 중요도 스코어링 → color_intensity (0~1)
    ↓
[5] 임베딩 → Milvus 저장 (벡터 + 메타데이터)
    ↓
[6] Streamlit 뷰어: 색 농도 표시 → HITL 수정/삭제 → 재임베딩 → 재저장
    ↓
[7] RAG 검색 + 리랭킹
```

## Phase 1 상세 — 전처리 + HITL + RAG

### 1-A. 전처리 파이프라인

- **classifier.py**: 정규식 휴리스틱(논문/법령/뉴스) → 미확정 시 LLM 폴백
- **chunkers/**: 3종 청커 병렬 실행, 문서별 최고 점수 채택
  - `llm_regex.py`: 문서 앞부분 8,000 토큰 → LLM이 정규식 1개 생성 → 전체 적용
  - `split_merge.py`: 2-pass (재귀 분할 → 탐욕 병합), 법령 조항 구분자 지원
  - `recursive.py`: 구분자 계층(\n\n → \n → . → 공백) 재귀 분할
- **metrics.py**: 5지표
  - SC: 토큰 크기 범위 준수 비율
  - BI: 구조 블록(제목/표/코드펜스) 보존 비율
  - ICC: 청크 내 문장-전체 임베딩 코사인 유사도 평균
  - DCC: 청크-슬라이딩윈도우(3,000 토큰) 유사도
  - RC: 대명사-개체 동일 청크 존재 비율 (영어 한정, 한국어 스킵)
- **normalize.py**: >1,100 토큰 재분할, <100 토큰 인접 병합

### 1-B. 중요도 스코어링

- **scoring.py**: 4요소 결합 → importance_score(0~1) → label(Core/Support/Context/Noise)
  - 위치 가중치: Abstract/Conclusion +0.3, Acknowledgement -0.5
  - 키워드 밀도: 도메인별 핵심어 매칭
  - 인용 밀도: [N] 패턴 카운트 (논문 한정)
  - LLM binary: "핵심 주장인가?" 판단 (선택적)
- **color_intensity** = quality_weight * quality_total + importance_weight * importance_score

### 1-C. Milvus 저장

- `MilvusClient("synapse.db")` 로컬 시작, 추후 `uri=http://localhost:19530` 전환
- Payload: text, source, doc_type, section, chunk_scores_total, chunker_used, importance, importance_score, color_intensity, user_adjusted

### 1-D. HITL 문서 뷰어

- 색 농도 렌더링: color_intensity(0~1) → rgba 배경색 (진할수록 높은 품질/중요도)
- 저점수 청크: 텍스트 수정 또는 삭제 → 재임베딩 → upsert, user_adjusted=true 기록
- 요약 대시보드: 총 청크 수, Core/Support/Context/Noise 분포

### 1-E. RAG 검색 + 리랭킹

- **retriever.py**: Milvus 시맨틱 검색 + importance_score 가중 부스팅
- **reranker.py**: 쿼리-청크 코사인 유사도 기반 리스코어링, original(0.4) + rerank(0.6) 가중합

## Phase 2 상세 — Neo4j 그래프

- **neo4j_client.py**: Document/Chunk/Keyword/Concept 노드 + 관계 에지
- **관계 그래뉼래리티** — 문서 유형별 선택:
  - `word_sentence`: Keyword → Chunk (APPEARS_IN)
  - `sentence_sentence`: Chunk → Chunk (FOLLOWS, 순차)
  - `word_word`: Keyword → Keyword (CO_OCCURS, 슬라이딩 윈도우)
- 키워드 추출: TF 기반 경량 추출 (stop-word 필터, 한/영 지원)
- 쿼리: get_related_concepts(), get_document_graph()

---

## Phase 3 상세 — Multi-Agent (LangGraph)

- **Supervisor 패턴**: Orchestrator → Search/Graph → Analyst → Writer
- **조건부 루프**: Analyst가 정보 부족 판단 시 Search/Graph 재호출 (max 5회)
- **state.py**: 에이전트 간 공유 상태 (query, search_results, graph_insights, analysis, report)
- **nodes.py**: 4개 에이전트 노드 함수 (orchestrator, search, graph→analyst, writer)
- **graph_builder.py**: StateGraph 조립 + compile → run_research(query)

## 실행 방법

### 백엔드

```bash
cd Synapse/backend
pip install -r requirements.txt
# .env 파일에 ANTHROPIC_API_KEY 설정
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 프론트엔드

```bash
cd Synapse/frontend
streamlit run app.py --server.port 8501
```
