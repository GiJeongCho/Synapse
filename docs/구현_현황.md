## 0. 한눈에 보는 에이전트 사용 흐름 (중요)

Meta-Agent로 만든 에이전트는 **생성 → (설정 확인) → 실행 / 스케줄 등록** 단계를 거친다.
생성만 하면 자동으로 돌지 않는다. 아래 흐름을 따라야 메일이 발송된다.

```
1) 에이전트 생성   (에이전트 생성 페이지)
   └ Meta-Agent가 실행 가능한 MCP 도구(Python 파일)를 생성·저장

2) 필수 설정 확인  (에이전트 관리 → 상세)
   └ SMTP/API 키 등 prereq 체크. ✗가 있으면 .env 채워야 함

3) 실행 방법 2가지
   ├ (A) 즉시 실행   : 에이전트 관리 → "실행" 버튼  → 도구 파이프라인 1회 실행
   └ (B) 자동 실행   : 스케줄 페이지 → cron 등록    → 주기적으로 자동 실행
```

> ⚠️ **스케줄 등록은 현재 "사람이 수동으로" 해야 한다.**
> 에이전트 생성 단계는 도구만 만들 뿐, 스케줄을 자동 등록하지 않는다.
> "매일 9시 10분", "1시간마다" 같은 표현이 요청에 있어도, 실제 cron 등록은
> 스케줄 페이지에서 직접 해야 자동 발송이 시작된다.
> (자동 등록은 향후 개선 항목 — §8 참고)

## 1. 실행에 필요한 외부 서비스

### 필수

| 서비스 | URL / 포트 | 용도 | 비고 |
|--------|-----------|------|------|
| **Embedding API** | `http://ppsystem.kro.kr:5000/embed` | 텍스트 → 벡터 임베딩 | Milvus 적재·검색, Registry 매칭에 필수 (`Qwen/Qwen3-Embedding`, dim=1024) |
| **Milvus Lite** | 로컬 `backend/synapse.db` | Vector DB | 파일 기반, 별도 프로세스 불필요 |
| **Anthropic API** | 클라우드 (API 키) | LLM 호출 | Meta-Agent, 청킹/분류에 필요. `.env`의 `ANTHROPIC_API_KEY` |

### 선택 (없어도 폴백 / 부분 동작)

| 서비스 | URL / 포트 | 용도 | 폴백 |
|--------|-----------|------|------|
| **Rerank API** | `http://ppsystem.kro.kr:5000/rerank` | Cross-encoder 리랭킹 | `(검색점수 × 0.6) + (color_intensity × 0.4)` 가중합 |
| **SMTP (Gmail)** | `smtp.gmail.com:587` | 에이전트 메일 발송 | 없으면 메일 도구 실행 시 prereq에서 차단 |
| **Neo4j** | `bolt://localhost:7687` | Graph DB | GraphStore search 미구현 (LLM 기반 graph_agent로 대체) |

### 개발 서버 (포트 변경됨)

| 서비스 | 포트 | 실행 |
|--------|------|------|
| FastAPI | **2004** | `cd backend && uvicorn app.main:app --reload --host 0.0.0.0 --port 2004` |
| Vite dev | **2003** | `cd frontend && npm run dev` — `/api`, `/v1` → `:2004` 프록시, 자동 브라우저 오픈 |

## 2. 환경 변수 (.env)

`Synapse/backend/.env` 에 설정:

```env
# LLM
ANTHROPIC_API_KEY=sk-ant-...
LLM_MODEL=claude-haiku-4-5-20251001   # 비용 절감용 haiku

# Vector DB / Embedding
MILVUS_URI=backend/synapse.db
MILVUS_COLLECTION=synapse_chunks
EMBED_API_URL=http://ppsystem.kro.kr:5000
RERANK_API_URL=http://ppsystem.kro.kr:5000

# Graph DB (선택)
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password

# SMTP (에이전트 메일 발송용)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your_id@gmail.com
SMTP_PASSWORD=앱_비밀번호_16자리   # Gmail 2단계 인증 → 앱 비밀번호
SMTP_FROM=your_id@gmail.com
```

> **Gmail 앱 비밀번호**: 일반 로그인 비밀번호로는 SMTP 인증 불가.
> [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) 에서 발급한 16자리 사용.
> 네이버는 로그인 비밀번호 자체를 거부하므로 Gmail 권장.

## 3. Milvus 컬렉션

| 컬렉션 | 용도 | 자동 생성 |
|--------|------|-----------|
| `synapse_chunks` | 문서 청크 저장/검색 | 첫 upsert 시 |
| `synapse_agent_registry` | Meta-Agent가 생성한 에이전트 저장 (graph_structure 포함) | 첫 등록 시 |
| `synapse_mcp_tools` | MCP 도구 명세 (seed.json → 자동 시드) | 첫 검색 시 |

> 컬렉션은 `ensure_collection()`에서 항상 `load_collection()` 호출로 로드 상태 보장
> (Milvus Lite의 'released' 상태 오류 방지).

## 5. 모듈별 구현 상태

### IMPLEMENTED — 실제 동작

| 모듈 | 파일 | 설명 |
|------|------|------|
| **전처리** | `preprocessing/pipeline.py` | 분류→청킹→메트릭→정규화→스코어링→임베딩→Milvus |
| **Milvus** | `vectordb/milvus_client.py` | embed API 호출, upsert/search/delete/query, gRPC keepalive 설정 |
| **RAG 검색** | `services/rag/` | vector_store, retriever, reranker(외부 API+폴백) |
| **문서/검색 API** | `api/documents.py`, `api/search.py` | 업로드/청크 편집, hybrid_retrieve+rerank |
| **Meta-Agent 파이프라인** | `agents/meta_agent/` | Requirements→Tool→**Provisioner(실제 도구 코드 생성)**→Evaluator |
| **Meta-Supervisor** | `agents/meta_supervisor/` | Registry 조회 → Solo/Dual 분기 → 쌍방 진화 루프 (max_rounds=2) |
| **MCP 도구 생성** | `agents/meta_agent/nodes/provisioner.py` | LLM이 httpx/bs4/smtplib 기반 실행 코드 생성 → 파일 저장 |
| **MCP 도구 런타임** | `services/mcp/tool_runtime.py` | subprocess로 도구 실행, env 주입, 저장/목록/삭제 |
| **에이전트 실행기** | `services/agent_runner.py` | 도구를 fetch→check→summarize→email 순 파이프라인 실행, 결과 자동 전달 |
| **사전 요구사항 체크** | `services/prereq_checker.py` | SMTP/LLM/임베딩/스크래핑 + required_env 점검 |
| **스케줄러** | `services/scheduler/engine.py` | APScheduler(Asia/Seoul), cron 등록/해제/즉시실행/로그, 재시작 복원 |
| **Agent Registry** | `services/agent_registry/` | Milvus 기반 CRUD + 유사도 매칭 + 삭제(연관 도구 동반 삭제) |
| **MCP Registry** | `services/mcp/` | MCP 도구 검색 + seed.json 10종 |
| **5개 워커 에이전트** | `agents/{search,crawl,graph,analyst,writer}_agent/` | 각 graph.py 동작 (graph_agent는 Neo4j 스텁이라 LLM 기반) |
| **Research 워크플로** | `workflows/research/` | Supervisor ↔ 워커 루프 |
| **그래프 직렬화** | `services/graph_serializer.py` | LangGraph → React Flow JSON |
| **API** | `api/` | meta_agent, tools, schedules, workflows, agents, jobs, documents, search |
| **프론트엔드** | `frontend/src/pages/` | 대시보드/생성/흐름도/도구/스케줄 페이지 모두 API 연동 동작 |

### PARTIAL — 일부만 동작

| 모듈 | 동작 | 미동작 |
|------|------|--------|
| **GraphStore** | Neo4j 드라이버 연결 | `search()` 미구현 → graph_agent는 LLM으로 대체 |
| **하이브리드 검색** | Vector 검색 | Graph fusion(RRF) 미구현 |
| **문서 분류** | 휴리스틱 규칙 | LLM 폴백 (API 키 필요) |
| **인증** | dependencies 존재 | JWT 검증 스텁 |

### 주의 — LLM 생성 도구의 품질 편차

- Provisioner가 만드는 도구 코드는 **LLM 출력**이라 매번 다르다.
  환경변수명(SMTP_*)·반환 형식은 프롬프트로 강제하지만 100% 보장은 아니다.
- 실제 스크래핑 대상(Bloomberg/Yahoo 등)은 robots.txt·동적 렌더링으로
  본문이 안 잡힐 수 있다 → 요약이 비어도 메일 발송 자체는 동작.

## 7. 동작 가능한 E2E 플로우

### 문서 → 검색 (동작)

```
업로드 → 전처리 → 임베딩(embed API) → Milvus → /api/search/query → rerank → 결과
```

### Meta-Agent 에이전트 생성 → 실행 → 메일 (동작)

```
POST /api/meta-agent/create
  → Registry 조회 (HIT이면 재사용)
  → MISS: Solo(1회) 또는 Dual(Builder↔Critic, max_rounds=2)
  → Provisioner가 실행 가능한 도구(.py) 생성·저장 → 등록

POST /api/meta-agent/registry/{id}/run  (또는 스케줄)
  → prereq 통과 시 도구 파이프라인 실행
  → fetch → summarize → send_email → 수신함 도착
```
